# tasteful-todo — 설계 문서

- 날짜: 2026-08-23
- 상태: 승인됨 (초기 브레인스토밍 결과)
- 레퍼런스: [nocal.app](https://nocal.app/), [superfocus.me](https://www.superfocus.me/)

## 1. 제품 정의

> **목표(goal)에 연결된 task를 markdown으로 서술하고, 캘린더의 빈틈에 드래그해서 시간에 커밋하는 Mac 앱.**

코어 루프: **goal 선택 → task 작성(markdown) → 타임라인에 드래그 배치 → 실행/체크**

모든 화면 요소는 이 루프에 복무한다. 루프에서 벗어나는 기능(통계, 리뷰, menu bar)은 전부 v2 백로그로 보낸다.

### 계층 모델

| 층 | 질문 | 사는 곳 | 비고 |
|---|---|---|---|
| **Goal** (장기) | 왜 | `goals/*.md` 파일 하나 | Inbox 포함 |
| **Task** (단기) | 무엇 | goal 파일 안의 체크리스트 | 상태: 미배치(백로그) ↔ 배치됨 |
| **Time block** (오늘) | 언제 | `daily/*.md`의 시간 + 참조 | — |

**"daily task"는 별도 엔티티가 아니다.** task를 타임라인에 드래그하는 순간 그 task가 오늘의 task가 된다 — 같은 task의 두 상태(미배치/배치됨)이지 두 종류가 아니다. 분류는 사용자가 고민하는 것이 아니라 드래그라는 행동이 대신한다.

**Inbox**: 어떤 goal에도 속하지 않는 잡일(택배 반품, 세금 납부 등)을 위한 특수 goal 파일 `goals/inbox.md`. goal 목록 맨 위에 고정 표시한다. "goal을 정하기 전엔 task를 못 적는다"는 마찰을 없애는 완충재.

### 차별점

"markdown 기반 todo + calendar 연동"은 NotePlan 등 선행 제품이 존재한다. 이 제품의 차별점은 **Goal 컬럼**이다 — 모든 time block이 어느 목표에 복무하는지를 항상 보이게 하는 goal-anchored time blocking (Superfocus의 goal-to-action 철학 + nocal의 markdown 캘린더 결합).

## 2. 핵심 결정 사항

| 결정 | 선택 | 근거 |
|---|---|---|
| 저장 모델 | 진짜 .md 파일이 source of truth | "markdown 기반" 정체성, 파일 이식성, Obsidian/iCloud/git 호환 |
| 계층 모델 | Goal → Task → Time block. "daily task"는 별도 종류가 아니라 배치된 상태 | 사용자에게 분류 부담을 지우지 않음. Inbox goal이 무소속 task를 수용 |
| 파일 구조 | goal 파일 + daily note 혼합 | 표현력 최상. 상태 복제 금지 규칙으로 동기화 복잡도 억제 |
| 캘린더 연동 | EventKit 읽기 전용 (MVP) | 핵심 경험("빈틈에 계획을 박는다")은 살리고 양방향 동기화 복잡도는 회피 |
| 기술 스택 | Tauri + React/TypeScript | 웹 기술 활용. EventKit은 Swift 사이드카로 브리지 |
| menu bar | v2로 연기 | 메인 앱 코어 루프가 먼저 서야 의미가 생김 |
| 빌드 순서 | UI 선행(목업) → 파일 연동 → EventKit | 가장 위험한 가설(3-column UX가 좋은가)을 가장 먼저 검증 |

## 3. UI 구성 (3-column)

### Left — Goal 목록
- `goals/` 폴더의 .md 파일 목록. **Inbox가 맨 위에 고정**, 나머지 goal이 그 아래.
- 선택하면 main 컬럼에 해당 파일 로드.
- 각 goal에 미완료 task 수 뱃지 표시.
- 하단에 goal 추가 버튼(= 새 .md 파일 생성).

### Main — Markdown 에디터
- 선택된 goal 파일의 본문 편집.
- task는 `- [ ]` 체크리스트. 체크박스 클릭으로 토글.
- task 라인에 드래그 핸들 → 오른쪽 타임라인으로 드래그해 시간 배치.
- 에디터는 CodeMirror 6 기반의 심플한 편집 경험. 라이브 프리뷰 고도화는 v2.

### Right — 타임라인 (time blocking)
- 하루 단위 세로 시간축. 헤더에서 날짜 이동(오늘로 돌아오기 포함).
- **배경 레이어**: Apple 캘린더 일정 (읽기 전용, 반투명 표시).
- **전경 레이어**: 내 time block. task 드롭으로 생성, 드래그로 이동, 엣지 드래그로 리사이즈.
- task 없이 시간만 잡는 **free block** 허용 (예: `점심`).
- 같은 task를 여러 시간대에 배치 가능 (여러 세션으로 나눠 일하는 경우).
- **역방향 생성**: 빈 시간을 드래그하면 입력 팝오버가 뜬다. 제목만 입력하면 free block, **goal을 지정하면 그 goal 파일에 task가 생성**되고 daily note에는 참조가 기록된다 → main에도 task로 나타남. "goal에 소속되는 순간 task가 된다"는 계층 모델의 자연스러운 귀결.

## 4. 데이터 모델 (파일 포맷)

```markdown
# goals/사이드프로젝트.md
- [ ] 랜딩페이지 초안 ^a1b2
  - 서브 노트, 링크 등 자유 서술
- [x] 도메인 구매 ^c3d4

# daily/2026-08-23.md
- 10:00-11:30 [[사이드프로젝트#^a1b2]]
- 12:00-13:00 점심
```

### 규칙

1. **불변 규칙: task의 텍스트와 체크 상태는 goal 파일에만 존재한다.** daily note는 시간 범위 + 참조(또는 free block의 텍스트)만 가진다. 데이터가 두 곳에 복제되지 않으므로 동기화 충돌의 여지가 구조적으로 제거된다.
2. block ID(`^a1b2`)와 링크 문법(`[[파일#^id]]`)은 **Obsidian 호환**. Obsidian 사용자가 자기 vault를 그대로 쓸 수 있는 잠재적 경로를 열어둔다.
3. block ID는 task가 처음 타임라인에 배치될 때 자동 생성한다 (이미 있으면 재사용).
4. 타임라인은 daily note의 참조를 goal 파일에서 해석(resolve)해서 렌더링한다.
5. **타임라인에서 직접 생성 시**: goal을 지정하면 그 goal 파일 끝에 `- [ ] 제목 ^id`를 append하고 daily note에 참조를 기록한다. goal 미지정 시 daily note에 텍스트만 있는 free block으로 기록한다. 어느 쪽이든 불변 규칙 1은 유지된다.

## 5. 아키텍처 (Tauri)

### React/TS 프론트엔드
- 3-column UI 전체.
- **markdown 엔진을 독립 TS 모듈로 분리**: task 파싱, block ID 부여, 직렬화, 참조 해석. 이 모듈이 단위 테스트의 핵심 대상.
- 타임라인 렌더링 및 드래그 앤 드롭.

### Rust 코어 (Tauri commands)
- 파일 읽기/쓰기.
- `notify` crate 기반 파일 감시 → 외부 에디터(Obsidian 등)에서 수정 시 앱에 실시간 반영.
- 충돌 시 **파일이 항상 진실**이다.

### Swift 사이드카 (M3)
- EventKit에서 날짜 범위의 일정 목록을 JSON으로 반환하는 소형 헬퍼 바이너리.
- 인터페이스는 단일: `events(from, to) → JSON`.
- macOS 캘린더 권한(`NSCalendarsUsageDescription`) 처리 포함.

## 6. 마일스톤

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M1 — UI 목업** | in-memory 데이터로 3-column 전체 인터랙션 완성 | 코어 루프(선택→작성→드래그 배치→체크)가 목업 데이터로 끝까지 동작. UX 느낌 검증 |
| **M2 — 파일 연동** | 폴더 선택, .md 파싱/저장, 파일 감시 | 파싱 라운드트립 테스트 통과(파싱→직렬화→원본과 byte 동일), 외부 수정 실시간 반영 |
| **M3 — EventKit** | 읽기 전용 배경 일정 | 캘린더 권한 플로우 + 실제 일정이 타임라인 배경에 표시 |
| **v2 백로그** | menu bar(현재/다음 블록), 캘린더 양방향 동기화, 주간 뷰, 반복 task, 리뷰 화면 | — |

## 7. 엣지 케이스와 에러 처리

- **참조 깨짐** (goal 파일에서 task 삭제됨): 타임라인에 "missing" 블록으로 표시하고 원클릭 정리를 제공한다. 조용히 지우지 않는다.
- **외부 수정과 앱 수정의 경합**: MVP에서는 단순하게 — 파일 감시 이벤트 수신 시 앱 상태를 파일 기준으로 갱신한다. 정교한 병합은 필요성이 확인되면 이후 단계에서.
- **파싱 불가능한 라인**: 건드리지 않고 그대로 보존한다. 사용자의 markdown을 절대 훼손하지 않는 것이 원칙.

### 타이포그래피

- **Hahmlet** (500/600) — 디스플레이: 워드마크, goal 제목, 타임라인 날짜
- **IBM Plex Sans KR** (400/500/600) — UI·본문
- **IBM Plex Mono** (400/500) — 시간, markdown 문법, block id, 라벨(uppercase + letter-spacing)
- 앱에서는 `@fontsource` 패키지로 번들 (오프라인 동작)

### 시각 언어 규칙

1. **색은 goal이 소유한다.** goal의 dot·time block·시간 칩이 같은 색을 물려받는다. Inbox는 중립색 원형 dot.
2. **조작 가능 여부가 형태로 구분된다.** 캘린더 일정(읽기 전용)은 빗금 + 점선 보더, 내 time block은 컬러 배경 + 좌측 3px 솔리드 보더.
3. **markdown 흔적은 보이되 소음 없이.** block id는 희미한 모노스페이스로 라인 끝에, 배치된 task에는 goal 색 시간 칩.
4. **레이아웃 수치**: 컬럼 240px / flex(본문 최대 58ch) / 300px. 시간축 48px/시간, 15분 스냅, 최소 블록 15분. 창 최소 폭 1080px.
5. hover에서만 나타나는 것: task의 `⠿` 드래그 핸들, 블록 하단 리사이즈 핸들.

## 9. 테스트 전략

- **markdown 엔진 (핵심)**: 파싱/직렬화 라운드트립, block ID 부여, 참조 해석, 파싱 불가 라인 보존 — 단위 테스트로 커버.
- **타임라인 로직**: 시간 범위 파싱, 블록 겹침 배치 — 단위 테스트.
- **UI**: 코어 루프에 대한 가벼운 컴포넌트 테스트. E2E는 M2 이후 필요 시.
